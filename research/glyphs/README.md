# Dreams — каталог глифов

Открыть [`catalog.html`](catalog.html). Он работает как самостоятельный локальный HTML без сети: поиск по ID/символу/Unicode/наблюдению, фильтр уверенности, исходник и последняя восстановленная форма рядом. Для G17 используется отдельный чёткий референс пользователя.

- [`PIPELINE.md`](PIPELINE.md) — воспроизводимый пайплайн: лист реконструкции и ручные правки → SVG → TTF → проверки → proof.
- [`PLAN.md`](PLAN.md) — этапы и критерии готовности.
- [`identifications.json`](identifications.json) — редактируемый источник идентификаций, 28 стабильных ID.
- [`IDENTIFICATIONS.md`](IDENTIFICATIONS.md) — подробный разбор субагента Sol 6.1 / Medium.
- [`references/sources.json`](references/sources.json) — происхождение сохранённых изображений.
- [`references/provenance.json`](references/provenance.json) — координаты и timestamps исходных вырезок из видео.

После изменения JSON пересобрать HTML из корня Dreams:

```sh
python3 scripts/build-glyph-catalog.py
```

## Правила каталога

1. ID глифа не зависит от гипотезы о Unicode. Не переименовывать G01–G28.
2. Confidence описывает идентификацию, а не готовность изображения к релизу. `confirmed_by_user` — явное подтверждение пользователя; `high`, `medium`, `low` — степень обоснованности гипотезы; `unidentified` — подходящей гипотезы пока нет.
3. Отдельно хранить наблюдаемую геометрию, гипотезу и альтернативы. Отражение и поворот должны быть явными.
4. Светлые пересечения — сплошные штрихи. Старый метод `G − (R+B)/2` создавал ложные отверстия; исправленный extractor использует G без вычитания нейтральных бликов.
5. `restored-v5.png` — текущая версия реконструкции; оригинальные кадры приоритетнее её формы. GPT Image может менять контуры или соседние глифы: проверять каждую итерацию.
6. Каталог не назначает cmap и не меняет шрифт приложения. Эти действия относятся к следующим этапам плана.
7. Новую партию обработки задавать списком ID, конкретной целью, референсами и критериями приёмки. Результат — версия изображения, промпт и запись о визуальной проверке.

## Задание следующей итерации

Сначала проверить геометрически однозначные сопоставления на небольшом наборе, затем спорные знаки. Для каждого сравнения: исходный кадр, стандартный символ, предложенное преобразование, восстановленный контур в одинаковом размере. Подтверждённые G01/G02 и исправленные пересечения сохранить. Не запускать повторную генерацию всего листа ради локальной правки без проверки остальных 19 знаков.
