# Glyph restoration pipeline

Directed katakana construction is an independent research layer:
[Katakana stroke library](katakana/README.md). `make katakana` generates pressure-driven
editable contours and an animated catalogue; it does not replace the production font.

One deterministic run turns verified inputs into a font, editable SVGs and a report. The same inputs give **byte-identical** outputs. The `verify` command and the self-test check this.

```
reconstruction sheet (PNG) ┐
                           ├─ grid slicing ─ potrace ─┐
overrides/Gxx.svg ─────────┼──────────────────────────┴─ contour cleanup ─ TTF ─ checks ─ proof + report
film masks ────────────────┘                                                  (topology, IoU,
identifications.json ─ cmap                                                    winding, mirroring)
```

## Commands

From the Dreams root:

```sh
.venv/bin/python scripts/glyphs/pipeline.py build      # build research/glyphs/build/
.venv/bin/python scripts/glyphs/pipeline.py verify     # rebuild in a temporary folder and compare hashes
.venv/bin/python scripts/glyphs/pipeline.py adopt G04  # take a contour into manual editing
.venv/bin/python scripts/glyphs/pipeline.py lock       # accept an intentional change of the frozen inputs
.venv/bin/python scripts/glyphs/selftest.py            # check that every check catches its own defect
```

`build` exits with code 1 if at least one glyph fails a check. Warnings do not change the exit code but appear in the report and the proof.

Environment: `.venv` on Python 3.13, dependencies in [`scripts/glyphs/requirements.txt`](../../scripts/glyphs/requirements.txt), external tool `potrace` 1.16.

## Inputs

| What | Where | Rule |
|---|---|---|
| Parameters | [`pipeline.toml`](pipeline.toml) | font metrics, tracing, thresholds, per-glyph settings |
| Reconstruction sheets | `references/restored-v5.png` and later ones | **frozen** (hash in `inputs.lock.json`). Add a new GPT Image iteration as a new `[[sheet]]`, never overwrite old ones |
| Film masks | `sources/film-masks/Gxx.png` | **frozen**; copy of `artifacts/film-glyphs/gxx-mask.png`, provenance in `references/provenance.json` |
| Identifications | [`identifications.json`](identifications.json) | provide the cmap; may change freely |
| Manual edits | `overrides/Gxx.svg` | if the file exists it replaces the tracing of that glyph |
| Drawn Latin | `latin/*.svg`, `latin/glyphs.toml` | generated by `scripts/glyphs/latin.py` from the `[latin]` rules; freely editable (see below) |
| Latin prototype | `references/latin-specimen-v1.png` | **frozen**; only a reference for the proof |

If a frozen input changes, the build stops. This way a quiet swap of a sheet or a mask cannot turn into a "new" font.

## What happens

1. **Slicing.** Rows and columns of the sheet are found from the widest empty gaps in the projections. Every connected fragment is assigned to a cell by its centre, so separate strokes of ツ and ミ stay with their glyph.
2. **Scale and fit.** The bottom and top edges of the glyphs in a row are averaged with a median. The row height is mapped to `body_bottom…body_top`, with one scale for the whole sheet. A glyph is centred in the `advance` width; `dy` from the settings shifts it vertically.
3. **Tracing.** A cell is upscaled `upscale` times, binarised and traced by `potrace` with fixed parameters.
4. **Contour cleanup.** Every SVG element is processed separately, taking `fill-rule` into account, then all are merged: overlaps fuse into one contour instead of punching holes. An already clean contour keeps its points as they are. The resulting contour is written to SVG and read back until it stops changing, so a copy adopted without edits is rebuilt exactly the same.
5. **Font.** Cubic curves are converted to quadratic ones (`cu2qu`, error ≤ 1 unit). UPM 1024, advance 956 and the sum ascent + descent match `Matrix-Code.ttf`. The baseline is y = 0, the film glyph body is 0…780 (ascent 900 / descent 124 keep the cell centred on the body), and the time in `head` is fixed. Drawn glyphs get their standard codes ahead of the film hypotheses and no PUA code. Every glyph is available at PUA `U+E000 + number`; a standard Unicode value is assigned only with confidence of at least `unicode_min_confidence`. If several glyphs claim one code point, the more confident one gets it and the others get only a PUA code.
6. **Checks.** Every glyph is rasterised **from the built TTF** with FreeType and compared with the source data:
   - topology (components and closed holes) must match `expect` from the settings, or, if there is none, the topology of the sheet raster. **Gate**;
   - the IoU of the tracing with the sheet raster must be at least `min_iou_traced`. A **gate** for traced glyphs; for manual edits only a warning below `override_warn_iou`;
   - winding of every contour by the TrueType rules, taking nesting into account: outer strokes clockwise, holes counter-clockwise, islands inside holes clockwise again. **Gate**;
   - comparison with the film mask, straight and mirrored. If the mirrored variant is closer by `mirror_margin`, a **warning** is issued: this catches orientation errors like G06, G15, G20.

## Outputs (`research/glyphs/build/`, not in git)

| File | Purpose |
|---|---|
| `DreamsMatrix.ttf` | the font |
| `glyphs/Gxx.svg` | editable contour in font units, with guides |
| `glyphs.json` | per glyph: source, cmap, topology, scores, warnings |
| `manifest.json` | hashes of all inputs, tool versions and hashes of the outputs |
| `report.md`, `proof.png` | human overview: film frame, mask, sheet raster, TTF contour and overlay |
| `proof-latin.png` | Latin and digits on the metric lines next to the prototype, text lines |
| `raster/Gxx.png` | the cut-out from the sheet that was traced |

The strict outputs (TTF, SVG, `glyphs.json`) must match byte for byte on a rebuild. The proof and the report are for viewing.

## Editing a contour by hand

```sh
.venv/bin/python scripts/glyphs/pipeline.py adopt G06   # → research/glyphs/overrides/G06.svg
# edit in Inkscape / Illustrator / Figma / FontForge
.venv/bin/python scripts/glyphs/pipeline.py build
```

- The coordinate system is font units, with the y axis pointing down from the ascender. **Do not change the `viewBox`**: if an editor rescaled the document, the build refuses to read it.
- Draw inside the group `id="glyph"`. The light-blue guides (`id="guides"`, baseline and glyph body limits) are ignored even if the editor lost their ids, because they have no fill.
- Overlapping shapes are allowed and will be merged. `fill-rule="evenodd"` is honoured the way a browser would render it.
- If an edit intentionally changes the number of components or holes, set the new `expect` in `pipeline.toml`. Otherwise the build counts it as a breakage.
- To go back to the tracing, delete the file from `overrides/`.

## A new reconstruction iteration

1. Save the sheet alongside, for example `references/restored-v6.png`. Do not touch the old sheet.
2. Add a `[[sheet]]` with `id = "v6"`, the grid and the order of IDs.
3. For glyphs that should come from the new sheet, set `sheet = "v6"` in `[glyph.Gxx]`.
4. `pipeline.py lock`, then `build`. The proof shows whether the result got closer to the film frame.

## Limitations

- The film masks are blurry (40×59 px). Comparison with them is a guide, not proof. For nearly symmetric glyphs (G14, G15) the straight and mirrored variants hardly differ.
- The sheet raster was created by GPT Image. The pipeline guarantees reproducibility **from the sheet and the edits to the font**, not the correctness of the reconstruction itself: that is still decided by visual comparison with the film.
- The rights to contours derived from the film have to be clarified separately before the font is distributed (see [PLAN.md](PLAN.md), stage 5).

## Connection to Dreams

`scripts/build-app.sh release` first runs the pipeline, stops if the checks fail, and copies the resulting TTF to the resource `Sources/Dreams/DreamsMatrix.ttf`, then builds the app. Manual edits in `overrides/` automatically go into the next app build. (`scripts/release.sh` does not run the pipeline: it uses the committed TTF, so commit `Sources/Dreams/DreamsMatrix.ttf` after changing glyphs.)

In the Dreams window the «Восстановленные глифы» (Restored glyphs) switch selects the new font `DreamsMatrix-Regular` and all of its PUA glyphs (currently `U+E001…U+E01C`). Switching it off brings back the previous `Matrix-Code`. The choice is saved. Switching recreates the atlas and starts the rain with a new pass; the density, speed, fade and brightness settings are kept. The keyword text uses DreamsMatrix-Regular in both modes and is shown in capitals only (Latin and Russian Cyrillic). The case of the original messages in the feed is unchanged.

## Extension G21–G28

The `simple-forms-v1` batch adds eight forms: 8, 4, a colon, two slightly slanted bars, a dash, <, > and a plus. The primary film crops and exact coordinates are recorded in `references/simple-forms-v1-provenance.json`. The contours are a preliminary manual SVG reconstruction; glow and grain stay in the renderer. The Unicode values of the two bars and the dash are not fixed.

The eight files `overrides/G21.svg` … `G28.svg` are ready for editing. The source sheet `references/simple-forms-v1.png` is frozen as an independent comparison base; editing an SVG must not overwrite this sheet. The old G01–G20 are unchanged.

For uniform cells the sheet supports `body_bounds = [top, bottom]`: the local y coordinates of the body of a full-size letter in each row. They fix a common scale and baseline so that a row of short glyphs is not stretched to cap height. For the new sheet at 239×256 px per cell, `[30, 225]` is used. Old sheets without this field keep the earlier metric estimate.

After `pipeline.py build`, the command `.venv/bin/python scripts/build-glyph-catalog.py` updates the catalogue and the clean SVG previews from the contours actually built. The app picks all available BMP PUA glyphs (starting at U+E001) from `DreamsMatrix-Regular`, with no fixed count in Swift.

## Latin and digits (`latin-v1`)

The set A–Z, a–z, 0–9 is not restored from the film but **drawn by rules**. The letter skeletons come from the prototype (`references/latin-specimen-v1.png`: Y like ソ, J like ノ, f like ナ), and the drawing follows the film glyphs: straight strokes with soft ends, rounded joins, descending diagonals that leave in a curved sweep and taper to the tip.

All numbers are set by `[latin]` in `pipeline.toml`, not by individual glyphs:

| Rule | Value |
|---|---|
| Lines | baseline 0, x-height 560, cap height 780, ascender 800, descender −145 (short: lowercase letters from commands fit into the atlas window), Cyrillic tails −130, overshoot 12 |
| Weight (broad nib) | stroke width depends on direction: vertical `stem` 118, horizontal `hair` 104, diagonals in between; lowercase 5 % lighter |
| Crossbars | E F H P R B at 0.52 of cap height, a e at 0.55 of x-height |
| Widths | capitals 530, M W 600, lowercase 480, m w 560, digits 510 (tabular) |
| Terminals | straight strokes have a square end softened by the radius `soften`; sweeps taper to `taper_tip` |

```sh
.venv/bin/python scripts/glyphs/latin.py              # generate missing and unmodified SVGs
.venv/bin/python scripts/glyphs/latin.py --force A g  # redraw by the rules, overwriting a manual edit
```

The generator does not overwrite an SVG that was changed after generation: the hash of the generated version is stored in `latin/glyphs.toml`. The same file holds, for every glyph, a contract that the pipeline checks during the build (**gate**):

- `expect` — the number of components and closed holes;
- `lines` — which lines the top and bottom of the glyph sit on (`cap`, `x`, `asc`, `base`, `desc` or `free`), with the tolerance `line_tolerance`.

Digits and letters take the standard codes. The film glyphs G01 (5), G02 (0), G11 (1), G13 (7) remain available at their PUA codes, so the rain's repertoire does not change. The cell width (advance 956) is shared with the rain: right for vertical columns, but for a horizontal line of text the gaps between letters are large.

## Cyrillic (`cyrillic-v1`)

Basic Russian Cyrillic (66 letters) on the same `[latin]` rules. 47 glyphs are drawn in [`scripts/glyphs/cyrillic.py`](../../scripts/glyphs/cyrillic.py): the lowercase letters are mostly capital-like (в г к л м н т), so each letter is built by one function for both cases. 19 forms that coincide with Latin (А В Е К М Н О Р С Т Х, а е о р с у х, п = n) are aliases: the same contour under the Cyrillic code, `[alias]` in `cyrillic/glyphs.toml`. The tails of Д Ц Щ д ц щ end on the shared `tail` line = −140. Files are named by the letter: `cyrillic/Ж-uni0416.svg`. The proof is `build/proof-cyrillic-v1.png`.

## How to make edits

Edits come at three levels. The higher the level, the more glyphs change at once and the lower the risk of inconsistency.

**1. A rule for all glyphs.** Stroke weight, heights, crossbars, widths, tips — `[latin]` in `pipeline.toml`. After changing it, regenerate the sets and build:

```sh
.venv/bin/python scripts/glyphs/latin.py
.venv/bin/python scripts/glyphs/cyrillic.py
.venv/bin/python scripts/glyphs/pipeline.py build
```

The generators redraw only glyphs you have not edited by hand; edited ones are listed as `kept`.

**2. The construction of a glyph.** How a stroke runs (where the bend is, where the sweep goes, what tapers) — the letter's function in `latin.py` or `cyrillic.py`. After editing, regenerate only that glyph: `latin.py --force R`, `cyrillic.py --force Ж` (for Cyrillic you can write the letter itself).

**3. The contour by hand.** Open the SVG from `research/glyphs/latin/` or `research/glyphs/cyrillic/` in Inkscape, Illustrator or FontForge, edit the path inside the group `glyph`, save, run `build`. The light-blue lines in the file are baseline, x-height, cap height, ascender, descender: they show where a glyph has to stand.

- Do not change the `viewBox`. If an editor rescaled the document, the build refuses to read the file. Figma usually changes the `viewBox` on export, so for it export without cropping.
- A manual edit is protected: the generators will not overwrite it until you explicitly ask with `--force`.
- The build checks every glyph. If an edit accidentally filled a hole, detached a stroke or moved a glyph off its line, the build fails and `report.md` says exactly what is wrong. If this is intentional (for example the glyph now has two parts), fix `expect` or `lines` for that glyph in `glyphs.toml`.
- Editing the Latin A also changes the Cyrillic А (an alias). To separate them, replace the alias with a glyph of its own in `cyrillic.py`.

The film glyphs G01–G28 are edited the same way, with `pipeline.py adopt Gxx` and `overrides/` (see "Editing a contour by hand").

To get an edit into the app: `scripts/build-app.sh release` rebuilds the font, stops if the checks fail, and copies the TTF to `Sources/Dreams/`.

## Punctuation and the app's atlas window

The `latin-v1` set includes the 32 ASCII punctuation signs and `…`: tool call lines are printed in the rain as they are (`bash: git log --oneline -5 && git status`). The signs are drawn with the same brush: quotes, `!` and the comma taper in a sweep, brackets span from the ascender to the descender, and `+ - = < >` stand on a common axis.

The app draws a glyph with a 26 px font in a 64×64 cell and takes the central 28×28 px window from it (`[app]` in `pipeline.toml`, source — `glyph()` in `MatrixRain.swift`). The pipeline checks every glyph, film and drawn, for leaving this window (**gate**): such a glyph would be clipped on screen. This check is what forced the descender to be shortened to −145 and the accents of capital Ё and Й to be made compact. If the cell size in the app changes, update `[app]`.
