# Пайплайн восстановления глифов

Один детерминированный прогон превращает проверенные входы в шрифт, редактируемые SVG и отчёт. Одинаковые входы дают **побайтно одинаковые** выходы. Это проверяется командой `verify` и самотестом.

```
лист реконструкции (PNG) ─┐
                          ├─ нарезка по сетке ─ potrace ─┐
overrides/Gxx.svg ────────┼──────────────────────────────┴─ чистка контура ─ TTF ─ проверки ─ proof + отчёт
маски из фильма ──────────┘                                                         (топология, IoU,
identifications.json ─ cmap                                                          обход, зеркальность)
```

## Команды

Из корня Dreams:

```sh
.venv/bin/python scripts/glyphs/pipeline.py build      # собрать research/glyphs/build/
.venv/bin/python scripts/glyphs/pipeline.py verify     # пересобрать во временной папке и сверить хэши
.venv/bin/python scripts/glyphs/pipeline.py adopt G04  # взять контур в ручную правку
.venv/bin/python scripts/glyphs/pipeline.py lock       # принять намеренную смену замороженных входов
.venv/bin/python scripts/glyphs/selftest.py            # убедиться, что каждая проверка ловит свой дефект
```

`build` завершается с кодом 1, если хотя бы один глиф не прошёл проверку. Предупреждения код выхода не меняют, но попадают в отчёт и proof.

Окружение: `.venv` на Python 3.13, зависимости в [`scripts/glyphs/requirements.txt`](../../scripts/glyphs/requirements.txt), внешний инструмент `potrace` 1.16.

## Входы

| Что | Где | Правило |
|---|---|---|
| Параметры | [`pipeline.toml`](pipeline.toml) | метрики шрифта, трассировка, пороги, настройки глифов |
| Листы реконструкции | `references/restored-v5.png` и следующие | **заморожены** (хэш в `inputs.lock.json`). Новую итерацию GPT Image добавлять новым `[[sheet]]`, старые не перезаписывать |
| Маски из фильма | `sources/film-masks/Gxx.png` | **заморожены**; копия `artifacts/film-glyphs/gxx-mask.png`, происхождение в `references/provenance.json` |
| Идентификации | [`identifications.json`](identifications.json) | дают cmap; меняются свободно |
| Ручные правки | `overrides/Gxx.svg` | если файл есть, он заменяет трассировку этого глифа |
| Нарисованная латиница | `latin/*.svg`, `latin/glyphs.toml` | генерируются `scripts/glyphs/latin.py` по правилам `[latin]`; правятся свободно (см. ниже) |
| Прототип латиницы | `references/latin-specimen-v1.png` | **заморожен**; только референс для proof |

Если замороженный вход изменился, сборка останавливается. Так незаметная подмена листа или маски не превратится в «новый» шрифт.

## Что происходит

1. **Нарезка.** Строки и столбцы листа находятся по самым широким пустым промежуткам в проекциях. Каждый связный фрагмент относится к ячейке по своему центру, поэтому отдельные штрихи ツ и ミ остаются при своём знаке.
2. **Масштаб и посадка.** Нижние и верхние границы знаков в строке усредняются медианой. Высота строки переводится в `body_bottom…body_top`, масштаб общий для всего листа. Знак центрируется в ширине `advance`, `dy` из настроек сдвигает его по вертикали.
3. **Трассировка.** Ячейка увеличивается в `upscale` раз, бинаризуется и обводится `potrace` с фиксированными параметрами.
4. **Чистка контура.** Каждый SVG-элемент обрабатывается отдельно с учётом `fill-rule`, затем все объединяются: перекрытия сливаются в один контур, а не прорезают дырки. Уже чистый контур сохраняет точки как есть. Итоговый контур записывается в SVG и читается обратно, пока не перестанет меняться, поэтому принятая без правок копия пересобирается точно так же.
5. **Шрифт.** Кубические кривые переводятся в квадратичные (`cu2qu`, ошибка ≤ 1 единица). UPM 1024, advance 956 и сумма ascent + descent совпадают с `Matrix-Code.ttf`. Базовая линия — y = 0, тело фильмовых знаков 0…780 (ascent 900 / descent 124 держат ячейку отцентрированной на теле), время в `head` фиксировано. Нарисованные знаки получают свои стандартные коды раньше фильмовых гипотез и не получают PUA. Каждый глиф доступен по PUA `U+E000 + номер`; стандартный Unicode назначается только при уверенности не ниже `unicode_min_confidence`. Если на одну кодовую точку претендуют несколько глифов, она достаётся более уверенному, остальные получают только PUA.
6. **Проверки.** Каждый глиф растеризуется **из собранного TTF** через FreeType и сравнивается с исходными данными:
   - топология (компоненты и замкнутые дырки) должна совпасть с `expect` из настроек, а если его нет — с топологией растра листа. **Gate**;
   - IoU трассировки с растром листа не ниже `min_iou_traced`. **Gate** для трассированных глифов, для ручных правок только предупреждение ниже `override_warn_iou`;
   - обход каждого контура по правилам TrueType с учётом вложенности: внешние штрихи по часовой стрелке, отверстия против часовой, островки внутри отверстий снова по часовой. **Gate**;
   - сравнение с маской из фильма в прямом и зеркальном виде. Если зеркальный вариант ближе на `mirror_margin`, выдаётся **предупреждение**: так ловятся ошибки ориентации вроде G06, G15, G20.

## Выходы (`research/glyphs/build/`, не в git)

| Файл | Назначение |
|---|---|
| `DreamsMatrix.ttf` | шрифт |
| `glyphs/Gxx.svg` | редактируемый контур в единицах шрифта, с направляющими |
| `glyphs.json` | для каждого глифа: источник, cmap, топология, оценки, предупреждения |
| `manifest.json` | хэши всех входов, версии инструментов и хэши выходов |
| `report.md`, `proof.png` | обзор для человека: кадр фильма, маска, растр листа, контур из TTF и наложение |
| `proof-latin.png` | латиница и цифры на линиях метрик рядом с прототипом, строки текста |
| `raster/Gxx.png` | вырезка из листа, по которой шла трассировка |

Строгие выходы (TTF, SVG, `glyphs.json`) обязаны совпадать побайтно при повторной сборке. Proof и отчёт предназначены для просмотра.

## Ручная правка контура

```sh
.venv/bin/python scripts/glyphs/pipeline.py adopt G06   # → research/glyphs/overrides/G06.svg
# правка в Inkscape / Illustrator / Figma / FontForge
.venv/bin/python scripts/glyphs/pipeline.py build
```

- Система координат — единицы шрифта, ось y направлена вниз от ascender. **`viewBox` не менять**: если редактор перемасштабировал документ, сборка откажется его читать.
- Рисовать внутри группы `id="glyph"`. Голубые направляющие (`id="guides"`, baseline и границы тела знака) игнорируются, даже если редактор потерял их id, потому что у них нет заливки.
- Перекрывающиеся фигуры допустимы, они объединятся. `fill-rule="evenodd"` учитывается так же, как его отрисует браузер.
- Если правка намеренно меняет число компонентов или дырок, укажи новое `expect` в `pipeline.toml`. Иначе сборка сочтёт это поломкой.
- Чтобы вернуться к трассировке, удали файл из `overrides/`.

## Новая итерация реконструкции

1. Сохрани лист рядом, например `references/restored-v6.png`. Старый лист не трогай.
2. Добавь `[[sheet]]` с `id = "v6"`, сеткой и порядком ID.
3. Для глифов, которые нужно брать из нового листа, укажи `sheet = "v6"` в `[glyph.Gxx]`.
4. `pipeline.py lock`, затем `build`. В proof видно, стало ли ближе к кадру фильма.

## Ограничения

- Маски из фильма размытые (40×59 px). Сравнение с ними — ориентир, а не доказательство. Для близких к симметрии знаков (G14, G15) прямой и зеркальный варианты почти не различаются.
- Растр листа создан GPT Image. Пайплайн гарантирует воспроизводимость **от листа и правок до шрифта**, но не правильность самой реконструкции: её по-прежнему решает визуальная сверка с фильмом.
- Права на контуры, полученные из фильма, перед распространением шрифта нужно выяснить отдельно (см. [PLAN.md](PLAN.md), этап 5).

## Подключение к Dreams

`scripts/build-app.sh release` сначала запускает пайплайн, останавливается при провале проверок и копирует полученный TTF в ресурс `Sources/Dreams/DreamsMatrix.ttf`, затем собирает приложение. Ручные правки в `overrides/` автоматически попадут в следующую сборку приложения.

В окне Dreams переключатель «Восстановленные глифы» выбирает новый шрифт `DreamsMatrix-Regular` и все его PUA-глифы (сейчас `U+E001…U+E01C`). Снятый переключатель возвращает прежний `Matrix-Code`. Выбор сохраняется. Переключение заново создаёт атлас и начинает дождь новым проходом; параметры плотности, скорости, затухания и яркости сохраняются. Текст keywords использует DreamsMatrix-Regular в обоих режимах и отображается только прописными буквами (латиница и русская кириллица). Регистр исходных сообщений в feed не меняется.

## Расширение G21–G28

Партия `simple-forms-v1` добавляет восемь форм: 8, 4, двоеточие, две слегка наклонные полки, тире, <, > и плюс. Первичные film crops и точные координаты записаны в `references/simple-forms-v1-provenance.json`. Контуры — предварительная ручная SVG-реконструкция; свечение и зерно остаются в renderer. Unicode двух полок и тире не фиксируется.

Восемь файлов `overrides/G21.svg` … `G28.svg` уже доступны для редактирования. Исходный лист `references/simple-forms-v1.png` заморожен как независимая база сравнения; правка SVG не должна перезаписывать этот лист. Старые G01–G20 не менялись.

Для равномерных ячеек лист поддерживает `body_bounds = [top, bottom]`: локальные y-координаты тела полноразмерной буквы в каждой строке. Они фиксируют общий scale и baseline, чтобы строка из коротких знаков не растягивалась до cap height. Для нового листа 239×256px на ячейку используются `[30, 225]`. Старые листы без этого поля сохраняют прежнюю оценку метрик.

После `pipeline.py build` команда `.venv/bin/python scripts/build-glyph-catalog.py` обновляет каталог и чистые SVG-превью из фактически собранных контуров. Приложение выбирает все доступные BMP PUA glyphs (начиная с U+E001) из `DreamsMatrix-Regular`, без фиксированного количества в Swift.

## Латиница и цифры (`latin-v1`)

Набор A–Z, a–z, 0–9 не восстанавливается из фильма, а **рисуется по правилам**. Скелеты букв взяты из прототипа (`references/latin-specimen-v1.png`: Y как ソ, J как ノ, f как ナ), рисунок — от фильмовых знаков: прямые штрихи с мягкими концами, скруглённые стыки, нисходящие диагонали уходят изогнутым взмахом и сужаются к кончику.

Все числа задаёт `[latin]` в `pipeline.toml`, а не отдельные знаки:

| Правило | Значение |
|---|---|
| Линии | baseline 0, x-height 560, cap height 780, ascender 800, descender −145 (короткий: строчные из команд помещаются в окно атласа), хвосты кириллицы −130, overshoot 12 |
| Вес (широкое перо) | ширина штриха зависит от направления: вертикаль `stem` 118, горизонталь `hair` 104, диагонали между ними; строчные на 5 % легче |
| Перекладины | E F H P R B на 0.52 высоты прописных, a e на 0.55 x-height |
| Ширины | прописные 530, M W 600, строчные 480, m w 560, цифры 510 (табличные) |
| Окончания | прямые штрихи — квадратный конец, смягчённый радиусом `soften`; взмахи сужаются до `taper_tip` |

```sh
.venv/bin/python scripts/glyphs/latin.py              # сгенерировать недостающие и неизменённые SVG
.venv/bin/python scripts/glyphs/latin.py --force A g  # перерисовать по правилам, затерев ручную правку
```

Генератор не перезаписывает SVG, изменённый после генерации: хэш сгенерированной версии хранится в `latin/glyphs.toml`. Там же для каждого знака записан контракт, который пайплайн проверяет при сборке (**gate**):

- `expect` — число компонентов и замкнутых дырок;
- `lines` — на каких линиях лежат верх и низ знака (`cap`, `x`, `asc`, `base`, `desc` или `free`), допуск `line_tolerance`.

Цифры и буквы занимают стандартные коды. Фильмовые G01 (5), G02 (0), G11 (1), G13 (7) остаются доступны по своим PUA-кодам, репертуар дождя не меняется. Ширина ячейки (advance 956) общая с дождём: для вертикальных колонок это правильно, для горизонтальной строки текста межбуквенные промежутки велики.

## Кириллица (`cyrillic-v1`)

Базовая русская кириллица (66 букв) на тех же правилах `[latin]`. 47 знаков нарисованы в [`scripts/glyphs/cyrillic.py`](../../scripts/glyphs/cyrillic.py): строчные в основном капительные (в г к л м н т), поэтому каждая буква строится одной функцией для обоих регистров. 19 форм, совпадающих с латиницей (А В Е К М Н О Р С Т Х, а е о р с у х, п = n), — алиасы: тот же контур под кириллическим кодом, `[alias]` в `cyrillic/glyphs.toml`. Хвосты Д Ц Щ д ц щ заканчиваются на общей линии `tail` = −140. Файлы называются по букве: `cyrillic/Ж-uni0416.svg`. Proof — `build/proof-cyrillic-v1.png`.

## Как вносить правки

Правки бывают трёх уровней. Чем выше уровень, тем больше знаков меняется сразу и тем меньше риск разнобоя.

**1. Правило для всех знаков.** Толщина, высоты, перекладины, ширины, кончики — `[latin]` в `pipeline.toml`. После изменения перегенерировать наборы и собрать:

```sh
.venv/bin/python scripts/glyphs/latin.py
.venv/bin/python scripts/glyphs/cyrillic.py
.venv/bin/python scripts/glyphs/pipeline.py build
```

Генераторы перерисуют только знаки, которые ты не правил руками; правленые перечислит как `kept`.

**2. Конструкция знака.** Как идёт штрих (где изгиб, куда уходит взмах, что сужается) — функция буквы в `latin.py` или `cyrillic.py`. После правки перегенерировать только её: `latin.py --force R`, `cyrillic.py --force Ж` (для кириллицы можно писать саму букву).

**3. Контур вручную.** Открыть SVG из `research/glyphs/latin/` или `research/glyphs/cyrillic/` в Inkscape, Illustrator или FontForge, править путь внутри группы `glyph`, сохранить, запустить `build`. Голубые линии в файле — baseline, x-height, cap height, ascender, descender: по ним видно, где знак обязан стоять.

- `viewBox` не менять. Если редактор перемасштабировал документ, сборка откажется читать файл. Figma при экспорте обычно меняет `viewBox`, поэтому для неё нужен экспорт без кадрирования.
- Ручная правка защищена: генераторы её не затрут, пока явно не попросишь `--force`.
- Сборка проверяет каждый знак. Если правка случайно залила дырку, оторвала штрих или сдвинула знак с линии, сборка упадёт и в `report.md` будет написано, что именно не так. Если это сделано намеренно (например, у знака стало две части), поправь `expect` или `lines` этого знака в `glyphs.toml`.
- Правка латинской A меняет и кириллическую А (алиас). Чтобы развести их, нужно заменить алиас собственным знаком в `cyrillic.py`.

Фильмовые знаки G01–G28 правятся так же, через `pipeline.py adopt Gxx` и `overrides/` (см. «Ручная правка контура»).

Чтобы правка попала в приложение: `scripts/build-app.sh release` пересобирает шрифт, останавливается на провале проверок и копирует TTF в `Sources/Dreams/`.

## Пунктуация и окно атласа приложения

В набор `latin-v1` входят 32 знака пунктуации ASCII и `…`: строки вызовов инструментов печатаются в дожде как есть (`bash: git log --oneline -5 && git status`). Знаки нарисованы той же кистью: кавычки, `!` и запятая сужаются взмахом, скобки занимают высоту от ascender до descender, `+ - = < >` стоят на общей оси.

Приложение рисует знак шрифтом 26 px в ячейке 64×64 и берёт из неё центральное окно 28×28 px (`[app]` в `pipeline.toml`, источник — `glyph()` в `MatrixRain.swift`). Пайплайн проверяет каждый знак, фильмовый и нарисованный, на выход за это окно (**gate**): на экране такой знак был бы срезан. Именно эта проверка заставила укоротить descender до −145 и сделать компактной диакритику прописных Ё и Й. Если размер ячейки в приложении изменится, обнови `[app]`.
