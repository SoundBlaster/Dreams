# Katakana stroke library · v1

Формальная исследовательская библиотека для построения глифа из движения кисти.
46 базовых знаков, 108 направленных штрихов; все каллиграфические аннотации пока **draft**.
Цель — получить редактируемую конструкцию для восстановления Matrix glyphs.
Это не доказанная реконструкция шрифта фильма и не симулятор физики ворса.

## Три независимых слоя

1. **Skeleton / ductus:** какие штрихи входят в знак, их порядок и направление.
   Направленные SVG paths взяты из зафиксированной версии KanjiVG.
2. **Brush gesture:** профиль нажима вдоль каждого штриха, предварительная
   аннотация окончания, условная длительность. Это наши настраиваемые гипотезы.
3. **Outline:** объединение отпечатков кисти; затем необязательное зеркалирование
   и перенос в метрики Dreams. Glow, зерно и другие оптические эффекты остаются
   отдельной задачей рендерера.

**Направление движения не определяет закон изменения толщины.** На присланных
пользователем таблицах видны и тонкие выходы, и толстые окончания. Поэтому в модели
нет правила «каждая черта сужается к концу». Для большинства знаков пока назначен
нейтральный профиль; несколько знаков имеют явно предварительные аннотации.

## Контракт данных

Редактируемый файл: [library.json](library.json). Схема: `dreams.katakana-strokes/v1`.
Проверяющий loader: [katakana.py](../../../scripts/glyphs/katakana.py).
Геометрическая библиотека: [stroke_model.py](../../../scripts/glyphs/stroke_model.py).

| Поле | Семантика / проверка |
|---|---|
| `character`, `reading` | Unicode и чтение; ровно 46 базовых знаков в заданном порядке |
| `review` | `draft` либо `reviewed`; последнее назначается после человеческой сверки |
| `strokes[]` | порядок письма, каждый элемент — отдельное касание бумаги |
| `source_id` | ID направленного path в pinned SVG; порядок и количество сверяются |
| `path_override` | необязательная новая направленная траектория; исходный SVG сохраняется |
| `terminal` | `unspecified`, `tome`, `harai`, `hane`; аннотация, не скрытая правка геометрии |
| `profile` | имя общего профиля нажима |
| `pressure` | необязательная персональная замена: пары `[s, p]` |
| `pressure_evidence` | `design-hypothesis`: нажим не измерен по движениям кисти |
| `duration` | условные секунды анимации, `(0, 10]`; не измеренная скорость письма |
| `brush` | общие `width`, `aspect`, `angle`, `gamma` |

Одна траектория содержит один `moveTo`, линии/кривые и не замыкается.
Координаты — клетка 109 × 109, x вправо, y вниз. Кривая аппроксимируется адаптивно,
затем семплируется равномерно **по длине**, с шагом не более 0.45 единицы.
Изменение длины/числа Bezier segments не меняет смысл профиля нажима.
Нулевые траектории, NaN, неверные диапазоны, подмена источников и перестановка
штрихов отвергаются. Неизвестная версия схемы также отвергается.

```json
{
  "source_id": "kvg:030aa-s2",
  "terminal": "hane",
  "profile": "hane",
  "duration": 0.7,
  "pressure_evidence": "design-hypothesis"
}
```

### Нажим и толщина

Пусть `c(s)` — направленная центральная линия, `s ∈ [0, 1]` — доля её длины.
`p(s) ∈ [0, 1]` — **нормализованный управляющий нажим**, не сила в ньютонах.
Профиль задаётся опорными точками, обязательно начиная с `s=0` и заканчивая `s=1`.
Между точками используется shape-preserving cubic Hermite interpolation (PCHIP).
Значение и первая производная непрерывны по длине штриха; промежуточные точки
не обнуляют скорость изменения нажима. Нулевые касательные остаются у настоящих
экстремумов и явно заданных плоских участков. Выбросов за значения соседних точек нет.
Это общее правило для всех штрихов, одинаковое в preview и SVG export.
Допустимы несколько максимумов, утолщение конца, постоянный нажим и подъём кисти.

```text
neutral:  (0, .70) → (1, .70)
tome:     (0, .45) → (.15, .70) → (.70, .70) → (1, .85)
harai:    (0, .80) → (.16, .70) → (.52, .40) → (1, .00)
hane:     (0, .50) → (.12, .75) → (.80, .80) → (.90, .65) → (1, .00)
swelling: (0, .25) → (.25, .45) → (.60, 1.0) → (1, .80)
```

Это **пять художественных presets**, а не универсальные законы японской каллиграфии.
`tome` (止め) — остановка; она допускает полный, толстый конец.
`harai` (払い) — выход с постепенным снятием нажима.
`hane` (跳ね) — поворот с коротким выходом; поворот должен быть в траектории.
Просто назначить профиль `hane` прямому штриху недостаточно, чтобы получить крючок.
Окончания и траектории на бумажных образцах могут зависеть от инструмента и стиля.

В точке `c(s)` кисть оставляет эллиптический отпечаток:

```text
r(s) = width / 2 × p(s)^gamma
E(s) = c(s) + R(angle) × diag(r(s), aspect × r(s)) × unit_disk
glyph = union(E(s)) для всех штрихов
```

При нулевом нажиме нет отпечатка. Реализация аппроксимирует эллипс 32 вершинами
и объединяет участки непрерывного следа через Skia PathOps. Пересечения штрихов заполняются
через **union**, поэтому в перекладинах не возникают искусственные XOR-дырки.
Толщина поперёк движения дополнительно зависит от угла касательной относительно
эллипса: `2r × sqrt((n·u)² + aspect²(n·v)²)`, где `n` — нормаль к движению,
`u, v` — оси кисти. Угол кисти и aspect сейчас постоянны внутри одного глифа.

Ограничения v1: нет упругого запаздывания ворса, растекания, сухой кисти,
измеренной силы и зависимости нажима от скорости. Геометрическая точность ограничена
шагом семплирования и многоугольным отпечатком. Вращение кисти по ходу штриха и
калибровку по реальному инструменту можно добавить отдельными профилями позже.

Отпечаток аппроксимируется 32-угольником. Соседние отпечатки соединяются локальной
выпуклой оболочкой, после чего участки объединяются. Это непрерывный sweep: тонкий
конец доходит до точки снятия кисти и не распадается на отдельные точки. Оболочка
строится только между соседними отсчётами, не между разными штрихами или всем знаком.

### Калибровка ネ・マ・ス・セ

У ネ четыре индивидуальных `pressure` и `path_override`, настроенных по визуальным
признакам присланного пользователем образца: первый и четвёртый штрихи начинаются
остриём и набирают толщину, второй набирает вес у поворота и сужается к левому
нижнему концу, вертикаль заканчивается утолщением. Исходные KanjiVG SVG сохранены.
Это ручная конструкция с неизменным `review: draft`, не измеренная траектория кисти
и не точная копия образца. Поворот второго штриха имеет короткий угловатый участок;
асимметрию окончаний ещё нужно согласовать.

У マ и ス настроены заход и поворот длинного штриха с последующим снятием нажима,
а второй диагональный штрих начинается остриём и расширяется. У セ индивидуально
заданы верхний поворот, заход вертикали и нижняя горизонталь с полным окончанием.
Все шесть новых штрихов имеют персональные траектории и плавные профили нажима.
`studies.html` показывает четыре знака рядом в обычном и зеркальном виде;
ссылка на этот лист находится в каталоге рядом с экспортом SVG.

### Направленные пары シ/ツ и ソ/ン

У этих четырёх знаков индивидуально настроены все десять штрихов. Короткие черты
начинаются остриём и расширяются: у シ/ン они более пологие, у ツ/ソ — более крутые.
Длинный росчерк シ/ン начинается снизу слева и заканчивается сверху справа;
у ツ/ソ он начинается сверху справа и заканчивается снизу слева. Нажим набирается
у начала движения и снимается к его концу; это направление сохраняется при экспорте.
На `pairs.html` показаны обычные и зеркальные формы. Подписи со стрелками вычисляются
из фактических координат штриха и отражаются вместе с формой. Лист связан с каталогом
и первым листом этюдов. Все новые настройки остаются художественными гипотезами DRAFT.

### Перекладины オ・キ・ホ・モ

Настроены все 13 штрихов: плавный набор веса у правого окончания перекладин,
снятие кисти вверх-влево на крючках オ/ホ, усиление наклонной вертикали キ
и нижний поворот モ с полным окончанием. У オ диагональ постепенно сужается
по всей длине; у ホ два боковых штриха начинаются остриём и расширяются.
`crossings.html` показывает эту группу в обычном и зеркальном виде.
Проверки фиксируют заполненные пересечения, отдельные боковые черты ホ,
направление крючка и различие между снятием кисти и полным окончанием.
Это художественная калибровка DRAFT, а не измеренный нажим или точная обводка образца.

### Повороты ア・ウ・ワ・ヲ

У всех десяти штрихов заданы собственные траектории и профили. На поворотах ア/ウ/ワ
нажим усиливается, затем длинные росчерки постепенно сходят на остриё. Короткие
вертикали ウ/ワ сохраняют полное окончание. У ヲ выбран вариант присланного образца:
верхняя перекладина отделена, а нисходящая дуга соединяется со второй перекладиной.
Эта конструкция намеренно отличается от исходной траектории KanjiVG, которая
остаётся неизменной в `sources`; порядок и число штрихов сохранены.
`turns.html` показывает обычные и зеркальные варианты. Тесты проверяют просветы,
число отдельных частей и непрерывность тонких концов. Настройки остаются DRAFT.

### Зеркалирование

Сначала строится нормальный контур; затем применяется `x′ = 109 − x`.
Сохраняются номера штрихов, начало/конец и расположение нажима вдоль пути.
Отражается также форма отпечатка. Это отражение готового письма для Matrix,
а не инструкция заново написать знак зеркально правой рукой.
Ширина и высота преобразуются общими коэффициентами; короткие знаки не растягиваются
индивидуально до всей клетки. Эти метрики предварительные, не финальная подгонка фильма.

## Запуск и ручная правка

Используются существующие зависимости glyph pipeline; для JavaScript behavioral
checks — Node.js 18+. Из корня Dreams:

```sh
make katakana-check      # источники, данные + behavioral tests и две идентичные сборки
make katakana           # каталог, лист 46 форм и 92 SVG (обычные + отражённые)
python3 -m http.server 8767 --bind 127.0.0.1 --directory research/glyphs/build/katakana
```

Открой `http://127.0.0.1:8767/catalog.html`. Каталог работает и как автономный HTML,
без CDN и сети. Есть выбор знака/штриха, анимация, scrubber, стрелки направлений,
зеркалирование, график нажима, пять профилей и ширина кисти. Номера при отражении
остаются читаемыми. Визуальные регуляторы — временный preview; для сохранения
изменяй `library.json`. Ссылки SVG ведут на экспорт **с профилями библиотеки**,
а не с временными настройками preview.

1. Сверить порядок и направление с учебными образцами; для спорного конца оставить
   `unspecified` и нейтральный нажим.
2. Изменить отдельный профиль `pressure` или центральную линию `path_override`.
3. Пересобрать, сравнить обычный и зеркальный знак. Затем вручную поправить контур SVG.
4. **Скопировать** выбранный SVG из build в отдельный файл перед ручной правкой:
   build — воспроизводимый выход, повторный запуск его перезаписывает.
5. После визуального одобрения подключить отдельным изменением к existing glyph pipeline.
   SVG содержит `id="glyph"`, метрики и guides, совместимые с его override loader.

Текущие TTF, PUA-состав дождя и `pipeline.toml` не изменены. Автоматического adoption нет.
Репертуар v1: 46 современных базовых знаков; small kana, dakuten/handakuten,
исторические ヰ/ヱ и варианты начертания пока не входят.

## Источники и статус доказательств

- Две присланные таблицы пользователя — визуальные референсы направления и характера
  штрихов. Их происхождение и лицензия неизвестны; сами изображения сюда не включены.
- [KanjiVG format](https://kanjivg.tagaini.net/svg-format.html): источник направленных
  осевых траекторий и порядка, **не источник нажима**.
  Revision `70a0b7ae0c18ceb5cb358274b029cce0234a43bc`.
  [sources.lock.json](sources.lock.json) хранит URL и SHA-256 каждого исходного SVG.
- [Japan Foundation: Marugoto teacher notes](https://marugoto.jpf.go.jp/assets/docs/teacher/resource/starter_c/starter_competences_teachers_notes_EN.pdf)
  рекомендуют учебные анимации порядка катаканы для сверки написания.
- Оригинальные SVG с copyright headers находятся в `sources/` и не редактируются.
  Геометрия KanjiVG отличается от образцов пользователя и от фильма; это опорный
  skeleton, который ещё надо согласовать, а не эталон финального контура.

## Следующий проход

Проверено локально: 14 Python behavioral checks, две побайтно одинаковые сборки,
Node-проверка управления анимацией с ручным временем, `make lint`.
В Safari через CUA проверены обычный/зеркальный контур, выбор знака и штриха,
график и промежуточное состояние написания на 50%, а также общий proof.
Непрерывное воспроизведение RAF в фоне при CUA-проверке не подтвердилось;
это остаётся отдельной проверкой в активной вкладке. Проверки воспроизводимости
и геометрии не подтверждают правильность каллиграфических гипотез.

Сверить オ → G04, マ → G06, セ → G12/G17 и ス → G20. Это сопоставления-гипотезы,
а не новые Unicode assignments. Для каждого согласовать форму поворота, толщину
начала/конца и отражение, затем перенести одобренные контуры в шрифт.
