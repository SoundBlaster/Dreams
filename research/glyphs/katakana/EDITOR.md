# Редактор параметрических штрихов

Рабочий конвейер: **параметры → контур → SVG**. Генерация изображений не участвует.

## Запуск

```sh
make katakana
python3 scripts/glyphs/stroke_library.py serve
```

Открой `http://127.0.0.1:8767/editor.html`. Если сервер уже работает на этом порту,
достаточно пересобрать страницу и обновить вкладку. `make glyph-editor` выполняет
обе команды. Если раньше был запущен обычный `python3 -m http.server`, останови
его: для записи checkpoints нужен сервер `stroke_library.py` на том же порту.
Готовый `editor.html` также
самодостаточен: все данные и JavaScript встроены, внешних CDN/API нет. Для стабильного
browser storage предпочтителен постоянный localhost URL. Ссылка есть в каталоге.

## Как править

1. Выбери знак, затем штрих и его участок. Серые точки на траектории выбирают
   участки; цветные — начало, середина, конец текущего участка.
2. Перетаскивай цветные точки или задавай X/Y числами. Середина находится **на
   дуге** при t=0.5. Прямая использует только начало и конец. Для крючка/поворота
   добавь участок; ненужный можно удалить. Соседние участки сохраняют общую точку.
3. Задай максимальную толщину и её положение по **длине всего штриха**.
   Начальная и конечная толщины ограничены максимумом. Между ними используется
   плавная C1-интерполяция, без выбросов и ступенек. На стыке участков траектория
   сохраняет C0-связность; повороты не принудительно сглаживаются.
4. Выбери острое, тупое или слегка округлое начало/окончание независимо.
   Острое сводит ширину к нулю, тупое оставляет срез поперёк траектории.
   Округлое добавляет пологую полуэллиптическую крышку глубиной 17.5% толщины
   соответствующего конца. Её ширина задаётся слайдером толщины начала/конца;
   при нулевой толщине округления не видно. Превью и экспорт SVG используют
   один контур. Старые JSON сохраняют свои окончания без преобразования.
   Слайдер соответствующей толщины при
   остром окончании выключен, но его значение сохранено для возврата к тупому.
5. Ширина всего знака меняет его вытянутость, отражение применяется к готовому
   контуру. Смотри превью 20/26/32/48 CSS px без свечения. Это SVG preview,
   не FreeType/Metal и не окончательная проверка шрифта на дисплее.

Смена знака сохраняет его параметры. Undo/Redo действует на редактирование,
добавление/удаление штриха, сброс и импорт. История — до 40 действий в текущей
вкладке; сам проект автоматически сохраняется между перезагрузками. Новую
латинскую/кириллическую букву можно добавить по символу и построить из штрихов.
Готовые наборы латиницы/кириллицы пока не переведены в эту параметрическую модель.

## Сохранение и экспорт

- **Checkpoints · база проекта** — введи название и нажми **Создать checkpoint**.
  Tab в поле названия добавляет выбранный глиф в начало, например `オ · мягкий хвост`.
  Если глиф уже есть в названии, Tab переводит фокус дальше; Shift+Tab всегда идёт назад.
  Снимок всех знаков записывается на диск, независимо от browser storage.
  Список показывает название, локальное время и изменённые знаки. Первая версия
  содержит весь набор, поэтому в ней изменёнными перечислены все знаки.
  **Восстановить** загружает выбранный снимок как рабочую копию: историю не удаляет,
  текущие правки можно вернуть через Undo. Следующий checkpoint укажет восстановленную
  версию родителем, позволяя пробовать альтернативы. Открытие обычного JSON начинает
  правки от текущей вершины базы. Вторая вкладка со старым состоянием истории получает
  конфликт: обнови список перед повторным сохранением. Это не заменяет её рабочие правки.
- **Сохранить JSON** — все знаки и параметры; это основная переносимая копия.
- **Открыть JSON** — загрузить файл проекта. **Вставить JSON** — тот же импорт
  через текстовое поле, если системный файловый диалог недоступен.
- Неправильный формат, нечисловые координаты, разрывы участков, дубликаты знаков,
  нулевые штрихи и превышение лимитов отклоняются до замены проекта.
- **Экспорт SVG** — текущий знак с отражением и пропорциями, группа `id="glyph"`,
  viewBox `0 0 956 1024` и сохранённая атрибуция. Контур состоит из заполненных
  перекрывающихся участков с nonzero fill; штатный SVG loader объединяет их.
  JSON остаётся источником редактируемых параметров. Обратный импорт произвольного
  SVG в управляемые штрихи не реализован.
- Browser storage не заменяет JSON-копию: он привязан к браузеру и origin.

## База в Git

Файлы находятся в `research/glyphs/stroke-library/`:

- `history.json` — schema v1, текущая вершина и append-only список checkpoints:
  ID, parent, название, UTC timestamp, SHA-256 проекта, изменённые знаки и атрибуция.
- `projects/<sha256>.json` — неизменяемые проекты с параметрами, общие для
  checkpoints с одинаковым содержимым. SHA-256 проверяется при чтении.
- `.lock` и временные файлы не версионируются. Запись истории атомарна и защищена
  file lock; при ошибке записи предыдущая версия остаётся доступной.

Checkpoint сохраняет файл локально; **Git commit и push не выполняются автоматически**.
Чтобы версия попала в историю репозитория, закоммить `research/glyphs/stroke-library/`.
JSON-снимки сохраняют атрибуцию источников. Сервер слушает только `127.0.0.1`,
принимает запись только с того же origin и проверяет JSON той же моделью,
которую используют редактор и SVG-экспорт. Обычный статический HTML продолжает
поддерживать JSON/SVG, но запись в базу требует локального сервера.

Существующий JSON можно добавить без браузера:

```sh
python3 scripts/glyphs/stroke_library.py save /path/to/dreams-strokes.json --label 'Название версии'
```

База исследовательская: сохранение checkpoint не заменяет глифы шрифта приложения.

## Начальные данные и ограничения

46 знаков посеяны из направленных катаканных этюдов. Кубические centerlines
приближаются короткими квадратичными участками с проверкой отклонения в четвертях
кривой (порог 0.15 единицы). Профиль ширины редактора упрощён до начала/максимума/
конца; это новый инструмент дизайна, а не точная копия эллиптической кисти каталога.
Окончания пера и финальную форму пользователь задаёт через траекторию/ширину.
Ни один исходный знак не объявлен эталоном киношрифта.

Код — MIT. Исходные исследования и производные данные сохраняют
[атрибуцию KanjiVG / CC BY-SA 3.0](NOTICE.md). Экспорт не устанавливает шрифт
и не меняет ресурсы приложения.

## Проверено

- `make katakana-check`: 27 Python tests, поведение старого каталога, 8 новых
  проверок геометрии/данных и event/state suite редактора.
- Две сборки каталога, включая редактор, совпадают побайтно.
- 92 экспортированных SVG читаются и объединяются существующим SVG loader;
  площади обычных и отражённых контуров совпадают в пределах 2%.
- Safari/CUA: числовые координаты, слайдер максимума, отражение, Undo/Redo,
  восстановление после reload, загрузка JSON через вставку и отмена импорта.
- Реально скачанные JSON/SVG проверены с диска: SVG совпадает с геометрией
  скачанного JSON, включая внесённые изменения.
- Native pointer drag не подтверждён: CUA возвращает `noWindowsAvailable`.
  Преобразование координат отражённого drag и его Undo проверены event-тестом
  с DOM double; это не замена физической проверке перетаскивания в браузере.
- File picker в управляемом Safari показывает JSON, но оставляет Upload
  недоступным даже без accept-фильтра. Импорт вставкой проходит; успешное открытие
  через системный диалог пока не подтверждено.

## Изображения-референсы

Панель **Референсы на холсте** загружает несколько PNG, JPEG или WebP под контур
текущего знака. Потяни изображение для перемещения, угловые маркеры — для размера.
**Пропорции** сохраняет соотношение сторон; с выключенным флажком доступно свободное
растягивание, а Shift временно сохраняет пропорции. Координаты и размеры можно вводить
числами. Есть отражение по горизонтали/вертикали, прозрачность и блокировка от сдвига.

Изображения привязаны к символу, сохраняются отдельно в browser storage и не меняют
контур, preview, SVG или checkpoint проекта. **Сохранить референсы JSON** создаёт
переносимую копию всех изображений и их размещения; **Открыть референсы JSON** заменяет
рабочий набор референсов. Перед заменой сохрани текущий набор. Undo контуров не меняет
референсы. Для обводки заблокируй изображение после размещения.

Лимиты: 24 изображения, исходный файл до 20 МБ; при загрузке изображение уменьшается
до 1024 px по длинной стороне. При исчерпании browser storage появится сообщение —
сохрани JSON перед закрытием страницы. SVG как референс не загружается.

## Толщина при изменении пропорций

**Сохранять толщину при сужении** — отдельный режим каждого глифа. Без него
«Ширина всего знака» масштабирует весь контур по X: при 59% вертикальный штрих
толщиной 13 выглядит как 7,67, а горизонтальный остаётся толщиной 13. С включённым
режимом нормали и округлые окончания строятся в отображаемых координатах: ширина
знака меняется, толщина штрихов сохраняется независимо от направления. Профиль
толщины остаётся привязанным к длине исходной центральной линии.

Режим сохраняется как необязательное `preserveWidth` в JSON и checkpoints, работает
одинаково на холсте, в preview и SVG. В старых проектах выключен для сохранения формы.

## Вставка участков

**＋ До** и **＋ После** вставляют участок относительно выбранного, сразу выбирая
его для редактирования. Наведение или keyboard focus подсвечивает место присоединения.
Внутри штриха соседний участок делится пополам с сохранением кривой и соединений:
«До» делит предыдущий и выбирает его вторую половину, «После» делит следующий
и выбирает его первую половину. На границах штрих продолжается прямой по касательной
на 12 единиц холста, с ограничением координат 0…109; у края доступное направление
корректируется внутрь холста. Undo возвращает исходную форму. Максимум — 32 участка.

## Ориентиры шрифта

Переключатель **Метрики** показывает font cell и подписанные линии в координатах
экспорта. В блоке **Ориентиры шрифта** отдельно включаются Baseline, Cap/body height,
Meanline/x-height, Ascent/descent, Bounding box и Advance/line height. Meanline по
умолчанию выключена: x-height нужна прежде всего для латиницы. Выбор запоминается
в браузере и не меняет проект, checkpoints или SVG.

Метрики читаются при сборке редактора из `research/glyphs/pipeline.toml`:
UPM 1024, ascent 900, descent 124, advance 956, cap height 780, x-height 560.
Leading — 0 при отсутствии `font.line_gap`; line height = ascent + descent + leading.
Это номинальная строка шрифта, а не шаг строк дождя приложения. Baseline соответствует
Y=103,25 на рабочем холсте после преобразования `translate(96.5 74) scale(7 8)`.
Пунктирная bounding box считается по текущему контуру с учётом отражения, сужения
и режима сохранения толщины. Рамка font cell показывает advance и ascent/descent;
origin обозначен точкой на baseline у левой границы ячейки.

## Вписывание в высоту шрифта

Кнопка **Вписать в cap height / baseline** вверху правой панели равномерно масштабирует
весь текущий глиф, включая толщину и округлые концы. Верх/низ фактического контура
совпадают с cap height/baseline, по горизонтали глиф центрируется в ячейке.
Контрольные точки и профили штрихов сохраняются: размещение записывается отдельно
как `placement: {scale, x, y}` в JSON и checkpoints и применяется также в preview/SVG.
Координаты в полях остаются координатами до общего масштабирования; перетаскивание
точек учитывает размещение. На картинку-референс вписывание не влияет.

**Сбросить размещение** убирает общее размещение, сохраняя остальные правки.
Оба действия поддерживают Undo. Повторное вписывание без правок не накапливает
масштаб. После редактирования контура можно вписать заново. Масштаб ограничен
0,05…20; для слишком плоского контура появится сообщение без изменения формы.

### Слои и перемещение целого знака

Справа список «Слои · штрихи и участки» заменяет выпадающие списки.
Нажми штрих или вложенный участок, чтобы выбрать его для правки.
Кнопки добавления и удаления работают с этим выбором.

«Двигать знак» переключает холст на перенос всего глифа: тяни по холсту,
а с Shift — только по одной оси. В этом режиме референсы остаются на месте.
«Точки» возвращает редактирование отдельных точек и референсов.
Поля «Сдвиг знака X/Y» задают точный сдвиг в координатах холста,
Y растёт вниз. Сдвиг применяется после отражения и масштабирования.
Он сохраняется вместе с глифом в JSON, checkpoints и SVG; толщины и
координаты отдельных штрихов не меняются. Один перенос — один Undo.
«Сбросить размещение» сбрасывает и перенос, и масштаб вписывания.

### Соединения и выравнивание точек

«Соединение участков» задаётся отдельно для каждого штриха: текущий
автоматический вариант (по умолчанию), Miter, Bevel или Round. Miter
ограничивает выступ четырьмя половинами толщины и на слишком остром угле
переходит в Bevel. Настройка сохраняется в JSON/checkpoints и SVG.

При Shift-drag начала или конца участка точка выравнивается с противоположным
концом по ближайшей экранной оси. У прямого участка получается строго
горизонтальный или вертикальный отрезок; дуга сохраняет свой тип.
Для средней точки Shift ограничивает движение одной осью относительно
положения до перетаскивания. Соединённые соседние концы двигаются вместе.

### Линейки и пользовательские пресеты

«Линейки» показывает шкалы X/Y возле границ рабочей сетки. Ноль совпадает
с её левым верхним углом; единицы — координаты холста (0–109), Y вниз.
Это отдельная шкала от font units: baseline и cap height по-прежнему
отображаются в своих метриках.

Нажатие/перетаскивание на верхней линейке создаёт вертикальную направляющую,
на левой — горизонтальную. Линии добавляются и кнопками под холстом.
Перетаскивай линию в свободной области или треугольный маркер на линейке.
Если линия проходит через глиф, его точки имеют приоритет; используй маркер.
В списке можно выбрать линию, задать точную координату и удалить её.

Введи уникальное имя и нажми «Сохранить пресет». Пресет хранит копию
текущего набора; последующее движение линий его не меняет. «Применить»
заменяет текущие направляющие выбранным набором. До 64 линий и 32 пресетов.
Пресеты и текущие линии общие для всех знаков, автоматически сохраняются
в этом браузере. Они не входят в глифовый JSON/checkpoints/SVG и не меняют
форму глифа. Undo относится к глифам; ориентиры редактируются отдельно.
