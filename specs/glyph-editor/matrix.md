## Scenario review

| Scenario | What the recovered contracts explain | Remaining verification / owner |
| --- | --- | --- |
| Ordinary editing, independent copy, Undo | Editor validates transactions; geometry supplies contours; snapshot restores project | Browser event delivery and visual correctness need a new run tied to this baseline |
| Shared form appears in two glyphs with different offsets | Components owns master/reference identity; parent explicit edit mode guards mutation; geometry resolves each offset; checkpoint effective comparison lists both | Review source identity after project replacement and whole-glyph transforms; acceptance owner: glyph maintainer |
| Invalid JSON or missing component | Model rejects invalid structure/references before transactional import; prior project remains editable | File chooser, browser quota and download completion are external host behavior |
| Standalone editor, no checkpoint API | Same document remains editable; API failure is shown and JSON/SVG transfer remains available | CORS/file-origin differences are not validated by HC context resolution |
| Two tabs save with the same head | First published index advances head; second receives conflict; parent can refresh and retry | Actual concurrent browser sessions not executed here; test source is an expectation |
| Pointer cancellation or Shift on reflected/offset instance | Parent must invert glyph transform and offset; shared endpoints stay joined; guides/references have separate state | Cancellation/axis behavior needs device/browser observations for stronger claims |
| Storage quota, IO failure or power loss | Browser reports storage error; local snapshot precedes atomic index publication | No directory-fsync/crash-transaction guarantee; browser and disk are independent persistence domains |
| Save dispatched, user continues editing before receipt | POST serializes the project at dispatch; receipt identifies that snapshot | R1: current draft may be newer while parent ID/status are updated; no runtime freshness claim |

## Review backlog and limits

- **R1 — asynchronous checkpoint freshness (parent editor).** Source permits edits while a POST is awaiting its response. The returned parent/status need not describe the latest working draft. Decide whether UI should show a dirty-since-save state or gate edits. This pass records the condition; it does not change code.
- **R2 — export metrics (geometry + build parent).** SVG export cell/mapping has fixed 956×1024/7×8 constants, while guides also consume pipeline.toml metrics. Changes to font metrics require compatibility review; arbitrary configurations are not proven consistent.
- **R3 — film fidelity and style learning (glyph maintainer).** Geometric validity and shared forms do not establish likeness to film glyphs. The proposed 5–7 manual style exemplars and extrapolation still need owner review; no extraction/inference pipeline is asserted.
- **R4 — crash/concurrency/host coverage (checkpoint + browser owners).** flock/atomic replacement and optimistic checks are source observations, not a complete crash-recovery or security proof. Origins, quota, downloads and pointer lifecycle remain host-dependent.
- **R5 — runtime adoption (FontBuild owner).** No automatic path connects editor checkpoints to the installed app font. Recover that boundary before claiming end-to-end glyph delivery.
- **Acceptance:** this recovery requests review of the drafts and backlog; it neither accepts new requirements nor weakens existing user goals. Historical browser/tests reported during feature work remain historical and are not copied into this run as fresh results.
